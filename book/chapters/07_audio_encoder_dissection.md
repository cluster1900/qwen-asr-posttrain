# 第 7 章 听觉前端与音频编码器逐层拆解：声波如何变成模型能“读懂”的向量？

> **本章情绪定心丸**：哪怕你未来只打算微调纯文本大模型（如 Qwen3-8B），也强烈建议认真读完这一章！为什么？因为这里完整展示了**信号预处理 + 2D 卷积网络（CNN）+ 双向 Transformer 编码器（Encoder，结构与 BERT/ViT 一脉相承）+ 跨模态投影器（Projector）**四大经典模块。一章看懂它们，语音、视觉、文档 OCR 和纯文本编码器全都不在话下！

我们追踪一段真实的 **4 秒中文音频**（16 kHz 单声道 WAV，共 `64,000` 个数字），看它如何一级级穿过 `thinker.audio_tower`，最终浓缩成 `50` 个 1024 维高语义音频向量（总压缩比 `1,280 : 1`）。

## 7.1 第 0 层（无参数）：从空气振动到 128 维 Log-Mel 频谱图

### 1. PCM 原始波形归一化（`[64,000]`）
声音本质上是空气气压随时间的起伏。麦克风以 **16,000 Hz**（每秒拍 16,000 次快照）把声波录成 16 位有符号整数（范围 `-32768 ~ +32767`）。在本项目 `train/train_sft.py` 的 `load_audio()` 里，第一行预处理极其干净：

```python
samples = np.frombuffer(frames, dtype="<i2").astype(np.float32) / 32768.0
```

这一除，把所有采样点归一化到 `[-1.0, +1.0]` 之间。

### 2. 为什么不能把 64,000 个采样点直接塞进 Transformer？
两大致命原因：

1. **太长了！** 64,000 个点算 $O(N^2)$ 注意力要 $40$ 亿次计算，4 秒音频就能把显卡算死；
2. **时域太“乱”了！** 同一个汉字“啊”，声波稍微晚了 0.1 毫秒，波形数字就全变了，但它的**频率成分（共振峰）**却稳如泰山！

### 3. STFT 与 Log-Mel 滤波器组（`[64,000] → [1, 128, 400]`）
人类耳蜗本身就是一台精密的频率分析仪——对低频变化极其敏感（能听清 200 Hz 和 300 Hz 的音高差），对高频比较迟钝（分不清 6000 Hz 和 6100 Hz）。**Log-Mel 频谱图**就是模拟人耳设计的三步魔法：

1. **加窗切帧 + 短时傅里叶变换（STFT）**：每隔 `10 ms`（`hop_length=160` 点）切一段 `25 ms`（`n_fft=400` 点）的语音小窗，把时域波形拆解成不同频率的能量强度。4 秒音频恰好切出 **`400` 帧**（帧率 `100 Hz`）。
2. **Mel 梅尔刻度压缩**：把线性的频率轴映射到符合人耳听觉的梅尔刻度，用 **128 个三角形滤波器**汇总能量（`num_mel_bins = 128`），得到一张 **`128 × 400`** 的“声音热力图”！
3. **取对数（Log）**：人耳感知响度也符合对数律（分贝 dB），取对数后微弱的辅音（如“s”、“f”、“t”）不会被响亮的元音淹没！

> **这一层的作用**：把一维杂乱的声压数字，变成一张像“乐谱热力图”一样的二维图像 `[1, 128, 400]`——横轴是时间（400 帧），纵轴是音高/频率（128 频带），像素亮度是声音能量。

## 7.2 第 1–4 层：3×Conv2d 下采样 Stem 与 `conv_out` 通道映射

拿到 `[1, 128, 400]` 的声音热力图后，400 帧还是有点长（一段 30 秒音频会有 3,000 帧！），而且相邻几帧之间高度冗余（人说一个汉字平均要 200–300 毫秒，占 20–30 帧！）。

因此 Qwen3-ASR 音频编码器先用三层完全对称的 **2D 卷积 + GELU** 组成“听觉压缩机”（`downsample_hidden_size = 480`）：

| 层名 | 模块定义 | 输入形状 `[C, F, T]` | 输出形状 `[C, F, T]` | 精确参数量 |
| :--- | :--- | :---: | :---: | ---: |
| `conv2d1` | `Conv2d(1, 480, k=3, s=2, p=1) + GELU` | `[1, 128, 400]` | `[480, 64, 200]` | $1 \times 480 \times 9 + 480 = 4,800$ |
| `conv2d2` | `Conv2d(480, 480, k=3, s=2, p=1) + GELU` | `[480, 64, 200]` | `[480, 32, 100]` | $480 \times 480 \times 9 + 480 = 2,074,080$ |
| `conv2d3` | `Conv2d(480, 480, k=3, s=2, p=1) + GELU` | `[480, 32, 100]` | `[480, 16, 50]` | $480 \times 480 \times 9 + 480 = 2,074,080$ |
| 展平 + `conv_out` | `Linear(480×16=7680, 896, bias=False)` | `[50, 7680]` | **`[50, 896]`** | $7680 \times 896 = 6,881,280$ |

看这组维度缩变多么舒服：

- **时间轴**：`400 → 200 → 100 → 50`（总共 **$8\times$ 下采样**！从每秒 100 帧压缩到每秒 **12.5 帧**，即 **每 1 帧代表 80 毫秒的语音**——刚好约等于半个声母/韵母，既不丢信息又把序列长度砍到 1/8，Attention 计算量直接降到 $\frac{1}{64}$！）。
- **频率轴**：`128 → 64 → 32 → 16`，同时提取出 **480 个局部声学纹理通道**（比如浊音横条、爆破音竖条、摩擦音高频颗粒）。
- **`conv_out` 整合**：把每个时间步上残留的 `480 通道 × 16 频带 = 7,680` 维声学特征拼平，用一个无偏置线性矩阵压缩进编码器的标准宽度 **`d_model = 896`**，再加上 **正弦位置编码（Sinusoidal Positional Embedding）** 标明时间先后顺序！

::: tip 为什么这里用 2D 卷积而不是一开始就上 Transformer？
2D 卷积自带两大“物理天赋”：**局部相关性**（共振峰和辅音爆破都是相邻频带和时间点构成的局部图案）和**平移不变性**（无论你在第 1 秒还是第 3 秒说“北京”，同一个卷积核都能认出它）。如果去掉卷积直接上 Transformer，计算量会暴涨 64 倍，而且小数据上极难学会局部声学纹理。
:::

## 7.3 第 5–22 层：18 层 AuT 双向音频 Transformer 编码器

现在，张量形状变成了规规矩矩的序列 `[50, 896]`。接下来它会连续穿过 **18 层完全同构的 `Qwen3ASRAudioEncoderLayer`**（`encoder_layers = 18`）。

### 单层 AuT 编码器拆解（精确 `9,645,440` 参数/层）
与后面要讲的“只能看过去、不能看未来”的因果语言解码器不同，听觉编码器采用的是**双向注意力（Bidirectional / Windowed Attention）**——听声音时，把前后几百毫秒的协同发音合起来一起看，才能听清含混的字音！

单层内部结构遵循标准的 **Pre-LN Transformer Encoder**：

$$\begin{aligned}
\mathbf{h}_1 &= \mathbf{x} + \text{MHA}\big(\text{LayerNorm}_1(\mathbf{x})\big) \\
\mathbf{h}_2 &= \mathbf{h}_1 + \text{FFN}_{\text{GELU}}\big(\text{LayerNorm}_2(\mathbf{h}_1)\big)
\end{aligned}$$

精确核对单层的每一块积木：

1. **`self_attn_layer_norm`**（LayerNorm, 896）：$\gamma, \beta$ 共 `1,792` 参数。
2. **多头双向自注意力（`self_attn`）**：`14` 个注意力头，每头维度 $896 \div 14 = \mathbf{64}$。
   - `q_proj`, `k_proj`, `v_proj`, `o_proj` 四个方阵各为 `896 × 896 + 896`（有 bias）= `803,712`，4 个合计 **`3,214,848`** 参数。
   - *注*：为了支持长达几十分钟的流式/超长音频而不爆显存，AuT 采用了动态窗口切块注意力机制（配置中的 `n_window` / `conv_chunksize`），把长音频切成窗口分批做局部双向建模。
3. **`final_layer_norm`**（LayerNorm, 896）：`1,792` 参数。
4. **前馈网络（`fc1 → GELU → fc2`）**：维度扩展 4 倍（`896 → 3584 → 896`，有 bias）：
   - `fc1`: `896 × 3584 + 3584 = 3,214,848`
   - `fc2`: `3584 × 896 + 896 = 3,212,160`
   - 合计 **`6,427,008`** 参数。

把这四项加起来：
$$1,792 + 3,214,848 + 1,792 + 6,427,008 = \mathbf{9,645,440 \text{ 参数/层}}$$
乘以 **18 层** = **`173,617,920`** 参数！

### 这 18 层从底层到高层，各自到底在学什么？
声学探针（Probing）研究揭示了音频 Transformer 极其迷人的分层演化规律：

- **浅层（第 0–5 层）**：声学去噪与音素切分——把背景白噪声、空调嗡嗡声、房间混响尾音剥离，锁定清音/浊音边界和声调曲线；
- **中层（第 6–12 层）**：音节与词组组装——把相邻 3–4 帧（240–320 ms）拼成完整的汉语拼音声韵调（如 `b-ei-3`、`j-ing-1`）；
- **深层（第 13–17 层）**：语境消歧与语义对齐——结合整句语调和上下文，区分“北京”还是“背景”，输出高度抽象的语义声学向量。

## 7.4 第 23–25 层：跨模态投影器（`ln_post → proj1 → GELU → proj2`）

走出第 18 层音频编码器，我们手里的张量是 `[50, 896]`。但它面临一个尴尬的语言障碍：

- 听觉编码器的母语是 **896 维声学特征空间**；
- 右侧 Qwen3-0.6B 语言解码器的母语是 **1024 维语言词向量空间**。

维度都不一样，怎么对话？于是架起一座三步走的**跨模态翻译桥（Multimodal Projector / Adapter）**：

```python
# 对应 modeling_qwen3_asr.py 中的音频输出投影头
hidden_states = self.ln_post(hidden_states)   # LayerNorm(896):         1,792 参数
hidden_states = self.proj1(hidden_states)     # Linear(896 -> 896):   803,712 参数
hidden_states = self.act(hidden_states)       # GELU 非线性翻译弯折
hidden_states = self.proj2(hidden_states)     # Linear(896 -> 1024):  918,528 参数
```

三层加起来仅 **`1,724,032`** 参数（占全模型仅 0.22%），却承担了最神奇的使命：**把“听觉坐标系”里的声学概念，精准旋转、对齐、投射到“语言坐标系”里对应的汉字概念附近！**

::: warning 为什么本项目后训练选择“冻结整个 Audio Tower + Projector”，只微调语言解码器 LoRA？
这是新手最容易纠结的架构决策。答案取决于你的**数据规模**与**任务目标**：

- **当你的目标数据只有几千到几万条（如本项目 19,685 条 AISHELL-1 物理增强数据）**：基座音频编码器已经在百万小时级多语种带噪数据上锤炼过，强行放开训练不仅显存暴涨，还极易把泛化极强的声学底层特征“过拟合”到你手头那几个有限的房间/说话人上！冻结听觉侧、只给语言侧挂 458 万 LoRA，就像保留一双好耳朵，专门训练大脑的“抗噪听辨与纠错推理”，实验证明这能在真实未见过的 AliMeeting 会议室远场录音上实现显著正向泛化（净减 40 字编辑！）！
- **什么时候才应该解冻 Audio Tower 或 Projector？** 当你拥有**数千小时以上**的全新领域声音（如全新小语种、特定方言、工业设备异响声纹），原编码器连基本音素都听不出来时，才需要分阶段解冻 Projector 乃至编码器顶层。
:::
