# 第 11 章 后训练第三站：在线 RL / GRPO、k3 KL 与严谨评测门禁体系

> **本章情绪定心丸**：提到“强化学习（RL）”，很多人脑海里立刻响起警报——马尔可夫决策过程、贝尔曼方程、Actor-Critic、优势估计 GAE……听着就想关书。好消息是：**大模型时代最火的在线强化学习算法——GRPO（Group Relative Policy Optimization，DeepSeek-R1 与本项目 `group_pg_mixed_v1` 同源的核心范式）——已经把复杂到发疯的 Critic 网络彻底删掉了！** 这一章我们用 10 分钟讲透 GRPO 原理、奖赏函数防作弊、`k3` KL 散度的绝妙数学，以及最难能可贵的**“统计学门禁与诚实止损”工程铁律**。

## 11.1 为什么学完 SFT 和 DPO 还要谈在线 RL（GRPO）？

SFT 和 DPO 都是**离线训练（Off-policy）**：模型只能被动看事先准备好的静态文本，**从未在训练循环里自己动手生成过句子**。这就导致了“训练-推理鸿沟（Exposure Bias）”：

- 我们真正关心的业务指标——比如代码单元测试能不能通过、数学题最终答案对不对、或者语音识别的 **CER（字错误率）**——都是**不可微的离散指标**，没法直接求导！
- **在线 RL / GRPO** 打破了这个僵局：**让当前策略 $\pi_\theta$ 现场自己动手生成 $G$ 个候选回答（Rollout）→ 扔给客观裁判算出标量奖励 $R_i$（比如 `1 - CER`）→ 奖优罚劣，直接朝着业务终极指标爬坡！**

## 11.2 从 REINFORCE 到 GRPO：为什么不需要 Critic 网络了？

策略梯度（REINFORCE）的直觉一句话就能说清：**“某个候选回答 $y_i$ 得分比平均分高（优势 $A_i > 0$），就增大模型生成它的概率 $\log \pi_\theta(y_i|x)$；得分比平均分低（$A_i < 0$），就压低它的概率！”**

损失函数简单得令人不敢相信：

$$\mathcal{L}_{\text{PG}} = -\frac{1}{G} \sum_{i=1}^{G} A_i \cdot \overline{\log \pi_\theta(y_i \mid x)}$$

怎么知道“平均分（Baseline）”是多少呢？

- **旧派 PPO**：专门额外训练一个同样大小的神经网络叫 **Critic（价值网络）** 来预测平均分——显存翻倍、超参难调、训练极易崩盘！
- **新派 GRPO / `group_pg_mixed_v1`**：**太简单了！同一道题让模型一次写 $G$ 份答卷（比如 $G = 4$ 或 $G = 8$），直接拿这 $G$ 份答卷的平均分当基准线！**

$$A_i = R_i - \frac{1}{G}\sum_{j=1}^{G} R_j \qquad \left(\text{DeepSeek 标准 GRPO 还会除以组内标准差 } \sigma_R\right)$$

## 11.3 RL 稳定不炸的四大工程命门（全来自真实 A100 代码）

看懂图 11-1，再吃透下面这四个直接决定 RL 成败的魔鬼细节（均实装于 `train/rl_contract.py` 和 `train/train_rl.py`）：

### 命门 1：Reward 函数设计必须防“作弊（Reward Hacking）”！
如果我们只写 $R = 1 - \text{CER}$，模型很快就会发现邪门歪道：比如遇到难听清的噪声句干脆输出空字符串（某些定义下字数少误差封顶），或者反复复读同一个高频词碰运气！
因此本项目设计了带双重防作弊惩罚与安全裁剪的奖赏函数：

$$R = \text{clip}\!\Big(1 - \text{CER} - 0.5 \cdot \mathbb{I}(\text{空输出}) - 0.5 \cdot \mathbb{I}(\text{异常重复}), \; -1.0, \; +1.0\Big)$$

同时，只要组内任意 1 个候选触发了**超长截断（`stop_reason == "length"`）或推理异常**，**整组直接作废丢弃**，绝不拼凑残缺组污染梯度！

### 命门 2：KL 散度为什么要选 Schulman `k3` 估计器？（高中泰勒展开 2 行秒懂！）
为了防止模型为了刷高 Reward 把正常说话能力训疯，RL 必须在损失里加上一项 **KL 惩罚 $\beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}})$**。
设每个 Token 上参考与策略的对数概率差为 $d = \log \pi_{\text{ref}}(y_t) - \log \pi_\theta(y_t)$：

- **朴素估计器 `k1`**：直接用 $-d = \log \pi_\theta - \log \pi_{\text{ref}}$。致命缺陷：单条样本上它**可能是负数**！如果某条样本恰好 $d > 0$，最小化它反而把策略推离参考模型，方差极大！
- **Schulman `k3` 估计器**（DeepSeek-R1 与本项目 `train/rl_contract.py` 第 198 行采用）：
  $$k_3(d) = e^{d} - 1 - d = \text{expm1}(d) - d$$
  用高中数学导数验一下 $f(d) = e^d - 1 - d$：
  - 求导 $f'(d) = e^d - 1$：在 $d=0$ 取唯一极小值 **$f(0) = 0$**，对任意实数 $d$ **恒有 $k_3(d) \ge 0$！绝不为负！**
  - 泰勒展开 $e^d \approx 1 + d + \frac{1}{2}d^2$，所以 $k_3(d) \approx \frac{1}{2}d^2$——平滑、低方差、而且期望严格无偏等于真实 KL 散度！

### 命门 3：全组同分（`zero_advantage`）必须连 KL 一起归零，且跳过无效步！
想象 4 个候选答卷得分完全一样（比如 4 个都 100% 全对，$R = [1, 1, 1, 1]$），此时所有 $A_i = 0$：

- **隐蔽大坑**：如果你虽然把策略梯度归零了，却**忘了把 KL 项一起归零**，或者把这种零信号组也算进了梯度累积窗口里，那么在没有正向激励的样本上，纯 KL 项会死命把模型往回拉，而且原本设定 4 组走一步，实际变成只有 1 条噪声句就强行更新一次 AdamW（引发剧烈梯度震荡）！
- **正确做法**（`train/rl_contract.py`）：
  1. 当全组同分（`zero_advantage=True`）时，**整组总损失（策略项 + KL 项）强制全为 `0.0`**；
  2. 开启 `accumulate_signal_groups_only: true`：不断 Rollout 直到攒满 4 个**真正产生非零信号的有效对齐组**，才执行一次 `optimizer.step()`！

### 命门 4：零额外显存的冻结参考模型切换顺序
如第 2 章剧透过的：把父版本 DPO 的 18 MB LoRA 权重深拷贝到 CPU 作为冻结参考并计算 SHA-256 校验码（每步验证参考权重 1 比特未改！）。每处理一个有效组时，**必须先在 `torch.no_grad()` 下换入参考 LoRA 算出所有候选的 `ref_logp` 并恢复策略权重，然后再对策略模型逐候选做前向和 `.backward()`**——既省掉 4× 激活显存，又彻底杜绝 PyTorch 原地修改 `_version` 崩溃！

## 11.4 真实战果与顶级工程操守：为什么我们诚实拒绝了 23 组 RL 实验？

在很多宣传文章里，永远是“SFT 涨 5 分 → DPO 再涨 5 分 → RL 又暴涨 10 分”的童话故事。但在真实的科研与工业工程里，**什么时候该大胆发布、什么时候该诚实踩刹车，才是区分业余玩家与顶级工程师的分水岭！**

来看本仓库跨越两代数据的真实 RL 对照实录：

1. **第一代合成数据（Phase 4 Pilot，`2026-10-23`）**：
   - 初始全句 RL 同样撞上了静音幻觉翻车；引入“组内等长差异对齐掩码 + 满 4 有效组更新 + 父版本 Anchor + `lr=1e-6`”后，对齐版 RL 在 Step 5 **一次性通过全量 2,500 条 val 门禁**（总编辑从 Base `2341` → SFT `2317` → DPO `2306` → **RL `2298`**, `raw_kl = 0.000338 <= 0.001`），并在独立新进程读回 `2500/2500` 零偏差后成功发布！
2. **第二代物理增强数据（Phase 6 Track 3B，`2026-11-25`）**：
   - 在引入 OpenSLR 28 实测 RIR 与标点恢复后，SFT + DPO 已经极其强悍（`val` 总编辑直降 `-125` 到 `2222`），DPO 冠军已经落进了一个极尖锐的局部最优点。
   - 我们先后跑了 3 轮共 **23 组 RL 实验**（修掉了 BF16 ULP 下溢改用 FP32 LoRA、按位移校准了学习率、过滤了 45% 满分组），结果 `23/23` 组在严格冻结门禁（`degraded_macro_delta <= 0.0` 且 `reward_delta >= +0.00002`）下均未越线（最优一组 `20261125T091000` Step 15 为 `tot=2228`, `dm=+0.00017`）。
   - **我们的决策**：**绝不事后放宽门禁阈值！绝不靠挑好看的子集凑数！** 诚实将 Stage 3 RL 闭环为 `gate_failed` 不发布，正式晋级已发布并读回验签的 DPO 冠军进入终局封存 Test 与真实会议 OOD 评测——结果 DPO 冠军在未见过的 AliMeeting 真实会议室上狂降 **`-40` 字编辑 / `-34` 词编辑**！

> **送给每一位读者的职业底线**：**“RL 未通过门禁并优雅回退至 DPO 冠军”不是失败，而是严谨工程体系的最高胜利！** 一个能把“确实没变好”拦截在上线之前的门禁系统，比一百个靠过拟合验证集自欺欺人的模型值钱一万倍。

## 11.5 评测、统计检验与“不靠感觉炼丹”的 Training Gym 体系

无论你训练什么模型，只要建立下面四根工程支柱，你的实验就拥有了大厂核心团队级别的可靠性：

1. **支柱一：零数据泄漏切分 + 物理级 Sim-to-Real 增强**
   - 切分 `train / val / test` 绝不能按单条随机 `random_split`！必须按**说话人 ID / 源句 ID / 物理房间家族（room_family）/ 噪声源 ID** 严格分组切分，并写自动化单测断言三集合交集为空！
   - 我们在 Track 2 到 Track 3B 的最大教训：**纯数学公式生成的理想指数衰减混响，存在严重的 Sim-to-Real 鸿沟**（真实会议室远场 CER 反而从 682 退化到 695）；换用 **OpenSLR 28 实测房间脉冲响应 RIR + 真实房间噪声** 后，同一套算法在真实未见会议室远场瞬间逆转为 **682 → 661（净减 `-21` 编辑！）**。
2. **支柱二：别凭单点涨跌欢呼！用配对簇 Bootstrap 算 95% 置信区间**
   - 看着验证集降了 0.2%，你怎么知道这不是随机运气？
   - 本项目 `evaluation/math_expectation.py` 采用**配对源簇自助法（Paired Source-Cluster Bootstrap, $B=2000$ 次重采样）**：把同一条原始语音派生的 5 个场景捆成 1 个独立簇，每次有放回抽取 500 个簇计算候选模型与基线的差值 $\Delta \text{CER}$、$\Delta \text{WER}$、$\Delta R$，输出 **95% 置信区间（CI）** 与 **后验胜率 $P(\Delta < 0)$**！只有当 95% CI 整体落在 0 以下（如 AliMeeting 上 `[-0.4746, -0.0243] pp`），才敢拍胸脯说这是统计学上板上钉钉的真提升！
3. **支柱三：多维度健康度门禁 + 封存 Test 只评一次**
   - 永远不要只盯一个总分！同步检查：**Clean 场景是否退化（防遗忘）**、**空输出率 / 重复率 / 超长截断率是否 `< 1%`**、**标点与格式是否被破坏**。
   - 选 Checkpoint 只看 `val`；封存的 `test` 与只读 `OOD` 在全流程终局**只允许评估一次**，严禁拿 `test` 指标回头调参！
4. **支柱四：原子断点续训 + SHA-256 血缘追踪 + 独立进程 Readback**
   - 云卡（尤其是 Colab）随时可能断连回收！每次保存 Checkpoint 必须同时原子落盘：`adapter.safetensors` + `optimizer.pt` + `scheduler.pt` + `rng_state.pt` + `sampler_state.json` + `sha256.json`，最后才原子更新 `latest.json` 指针。
   - **区分 `latest.json`（最新进度）与 `release`（门禁选中的最佳步）**：发布最终模型前，必须开一个**全新干净进程**重新加载基座 + 发布版 LoRA，跑一遍完整验证集，断言 `mismatch_count == 0` 才盖章 `published`！

1. GRPO 用“同题多候选组内均值”取代了笨重的 Critic 网络，让在线 RL 变得轻量且可直接优化 CER/代码/数学等不可微指标。
2. 记住 RL 四大稳定器：**防作弊裁剪 Reward + 非负低方差 `k3` KL + 零优势组全归零跳过 + 先算 Ref 再算 Policy**。
3. 真正的工程水平体现在 **零泄漏切分、真实物理数据、配对簇 Bootstrap 95% CI 与永不妥协的门禁纪律**。
